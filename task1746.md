# JADE-1746: Dump when resetting an LI shift

## Issue
Resetting an LI shift (supply types `V`, `K`, `E`) can dump. Ticket example: GBT, T04, `22.10-23.10`. Reported workaround: delete the workplace first.

## Evidence
ST22 confirms:

| Detail | Value |
|---|---|
| Runtime error | `ITAB_LINE_NOT_FOUND` |
| Exception | `CX_SY_ITAB_LINE_NOT_FOUND` |
| Class / method | `ZCL_IA_2WORKSHIFT->RESET` |
| Table / access | `LO_ORDERS->MAP`, index `1` |
| Failing statement | `IF lo_orders->map[ 1 ]-key IS NOT INITIAL.` |
| Dump timestamp | `17.11.2026 17:55:56 CET` |

## Root cause
Reset processes each workplace's orders. If the order map is empty, evaluating `[ 1 ]-key` raises an exception before `IS NOT INITIAL` can check the key. The later guarded `READ TABLE` is never reached. Removing the workplace avoids processing its empty order map, consistent with the reported workaround.

## Fix
File: `ZCL_IA_2RULES\ZCL_IA_2WORKSHIFT.abap`  
Method: `RESET`, around line `3136`.

Replace only the failing condition:

```abap
IF line_exists( lo_orders->map[ 1 ] ) AND lo_orders->map[ 1 ]-key IS NOT INITIAL.
```

ABAP short-circuits `AND`: if row 1 is absent, the key access is not evaluated. Order-status deactivation is skipped, while the existing safe read and subsequent order/vehicle/workplace cleanup continue unchanged. For a present row, the original non-initial-key check remains.
