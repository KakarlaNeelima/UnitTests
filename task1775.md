# JADE-1775: Manual routes reappear after deletion

## Issue
Removing a saved manual route from Train Formation and selecting **Save changes and close** removes it from the popup, but it reappears when reopened.

## Evidence
| Debug value | Observed data |
|---|---|
| Shift route cache `GO_SCHICHT->GT_TRASSEN` | 96 rows; includes manual trains `34192`, `34193`, `34194` |
| Manual route attributes | `DATA_ORIGIN = M`, `ZID_EIZ = 20`, `RICHTUNG = E`; each train has `REIHENFOLGE = 1` and `2` |
| Cleanup `LT_TRASSEN_DB`, before manual-origin filter | 18 rows, all EIZ `10`; origins blank or `V`, no `M` |
| Cleanup `LT_TRASSEN_DB`, after manual-origin filter | 0 rows |
| Same filter after the fix, observed in SAP | 3 rows: `34192`, `34193`, `34194`; EIZ `20`, direction `E`, sequence `1` |

The captured data identifies the affected manual routes; the specific train clicked for removal was not recorded.

## Root cause: why deletion is not persisted
Save calls `SAVE_DATA -> Z_SAVE_GBT -> SAVE_MANUAL_TRASSEN -> CLEANUP_MANUAL_TRASSEN`.

Cleanup obtains candidates through `ZCL_IA_2WORKSHIFT->GET_TRASSEN`, which calls `GET_TRASSEN_FOR_RICHTUNG`. That helper loops over EIZ values in ascending order (`10`, then `20`), but previously copied its working table only **before** the loop:

1. Processing EIZ `10` deletes all EIZ `20` rows from the working table.
2. Processing EIZ `20` reuses that reduced table and returns no southern routes.
3. Cleanup filters the returned routes to manual origin `M`, leaving **0 candidates**.
4. Its deletion loop is skipped: `DELETE_TRACKS` and `DELETE_TRAIN_MAINTDATA` are not called for the removed route. The saved route remains and is loaded again on reopening.

`V_GBT->ONACTIONBTN_REMOVE` only removes the context row; persistence depends on this cleanup.

## Fix
File: `ZCL_IA_2RULES\ZCL_IA_2WORKSHIFT.abap`  
Method: `GET_TRASSEN_FOR_RICHTUNG`

Sort the direction-filtered source once, then copy it **inside** the EIZ loop:

```abap
SORT lt_trassen BY (it_sort_order).

LOOP AT lt_eiz ASSIGNING FIELD-SYMBOL(<ls_eiz>).
  DATA(lt_trassen_eiz) = lt_trassen.
  DELETE lt_trassen_eiz WHERE zid_eiz <> <ls_eiz>-zid_eiz.
  " Remaining sequence-selection logic unchanged.
```

Each EIZ gets a fresh copy; direction and first/last sequence-selection rules remain unchanged. No controller or database-deletion logic was changed.

## Verification / impact
**SAP verification:** cleanup retains all 3 manual routes instead of 0; the user confirmed manual-route deletion now works. Broader regression checks remain pending: unchanged saves, adding manual routes, and both EIZ `10`/`20` in entry/exit directions, including unrelated routes and workplace arrival/departure times.
